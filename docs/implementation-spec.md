## 1. 概要

月給制・フレックスタイム制(コアタイムなし)の従業員向けに、**出勤するだけで金額と労働時間が
秒単位で積み上がっていく** のを見せるWebアプリ。目的は、増えていく数字を見て働くモチベーションを
高めること。

設計三原則:

- **計算は極力正確に** — 就業規則・労基法に照らした区分計算を裏側で行う
- **操作は単純に** — 平常時のボタンは「出勤 / 退勤 / 休憩」の3つだけ
- **表示はシンプルに** — 数字とバー・メーターだけで構成し、装飾は最小限にとどめる

サーバーを持たず、データは端末のブラウザ内(localStorage)にのみ保存する。一度開いたあとは
`sw.js`(Service Worker)がファイル一式をキャッシュし、通信が無い状態でも開ける(1.3参照)。

## 2. 画面構成

カード基調の1カラムレイアウト。上から順に次を積む。

| 位置 | 要素 | 内容 |
|---|---|---|
| ヘッダーカード | アプリ名・状態バッジ・カレンダー / 設定 / テーマ切替ボタン | 待機中 / 勤務中 / 休憩中 / 自動計測中 を色でも見分けられる |
| 操作バー | 出勤 / 退勤 / 休憩開始・終了(自動モード時は残業開始 / 終了も) | 押すたびに確認ダイアログを挟む |
| 最優先 | **① 今日の勤務** | 秒単位で増える金額(小数2桁)+ いまの区分と倍率。円の位が1つ増えるたびに短いパルス |
| 同列2枚 | **② 今日** / **③ 今月** | 金額 + 「労働時間 / 所定労働時間」。今月には先月同時点との差を添える。設定でそれぞれ非表示にできる |
| 横棒メーター | 今月の残業 | 0〜60時間の目盛りに、45h・60h・固定残業の位置を目印で表示 |
| 横棒グラフ | 先月との比較(同じ経過日数) | 今月・先月(同じ経過日数時点)を通常/残業の色分けで並べる。金額は出さない |
| 折りたたみ | 内訳と目安 | 既定は閉じている(2.2) |

金額の色(ゲージのトーン)は、いま加算されている区分によって静かに変わる。警告色・通知音は
使わない。

| 区分 | 色 |
|---|---|
| 所定内 | シアン |
| 法定内残業 | ブルー |
| 法定時間外(1.25 / 1.50) | アンバー |
| 深夜(22:00〜翌5:00) | バイオレット |
| 法定休日 | ピンク |
| 休憩中(カウント停止) | グレー |

出勤していないときは、その日の直近の勤務ぶんを静かに表示する。

### 2.1 ライト / ダーク

**初回起動は、端末のダーク設定に関わらず常にライトで開く。** ヘッダーのボタンで明示的に
切り替えると `wageTheme` に保存され、以後はその選択が使われる。色はすべて CSS のトークンで
定義しており、コンポーネント側に生の色を書かない。配色はパステル寄り(彩度を落とした
シアン・アンバー・グリーン・ブルー・バイオレット・ピンク)。

### 2.2 折りたたみの補助情報

- **今月の内訳** — 所定内 / 法定内残業 / 固定残業でカバー / 法定時間外(1.25・1.50)/ 法定休日 /
  深夜割増 / うち未入力の自動加算 / 基本給とは別の追加分
- **賃金の計算式** — 所定労働時間・月平均所定労働時間・基礎時給単価を、実際の数値を入れた式で示す
- **清算期間** — 対象期間、締め日まであと何日か(速報値である旨)、所定労働日数と総枠、
  法定労働時間の総枠、先月同時点の実績と差。所定の総枠が法定の総枠を超える設定になっている
  場合は、設定確認を促す一文を出す
- **残業時間の目安** — 今月の法定時間外、45時間・60時間・単月100時間までの残り、固定残業の
  消化状況、固定残業代が不足していないかのチェック
- **気づき** — 休憩未取得の目安
- **未入力の日** — 何日あるか、どの日か(催促や警告の体裁にはしない)
- **先月(確定)** — 前清算期間の合計

### 2.3 設定画面

初回起動時も2回目以降も同じ1枚の設定画面を使う。上から「基本給 → 出勤/退勤時間 → 休憩時間帯
→ 所定労働時間(自動計算・表示のみ)→ 所定労働日の曜日 → 祝日の除外 → 法定休日の曜日 →
年間所定休日数 → 賃金締め日 → 固定残業代 → メイン画面の表示項目 → 自動モード」の順。保存できない
入力があると、フォーム上部に赤い注記が出る。「データの保存とリセットについて」「金額の見かたと
注意」の説明を折りたたみで常設し、最下部に「すべてのデータを消す」(誤操作防止のため2回押し)。

### 2.4 カレンダー画面

**表示できる範囲は先月から3ヶ月先までの5ヶ月。** 端まで来ると前後の移動ボタンが無効になる。
週は日曜始まり。マスの色点で状態を示す。

| 色点 | 意味 |
|---|---|
| 緑 | 打刻あり(出勤した日) |
| 水色 | 有給休暇 |
| 紫(ピンク) | 法定休日 |
| バイオレット | 国民の祝日(所定休日として除外されている日) |
| グレー | 所定休日(法定超・通常の週休) |
| 琥珀 | 未入力(所定内として自動加算されている日) |

マスをタップすると、その日を「指定なし / 出勤 / 有給 / 会社休日」に変更できる日編集画面が開く。
祝日の場合は名称(例:「この日は『敬老の日』です」)を表示する。出勤を選んだ場合は時刻を入力でき
(翌日にまたがる指定も可)、法定休日として扱うかも選べ、**その日の休憩(昼休憩以外)も個別に
追加・修正・削除できる**。

## 3. 設定項目

上から「基本給 → 勤務時間 → 休憩時間」の順に並べ、**その3つから1日の所定労働時間が自動で
決まる**(入力項目ではなく計算結果を表示するだけ)。

| 順 | 項目 | 既定値 | 入力方法 |
|---|---|---|---|
| 1 | 割増の基礎になる月額(基本給+諸手当) | 未設定(例として 300,000 を表示) | 入力欄・マスク表示(「表示」ボタンで確認) |
| 2 | 出勤時間 / 退勤時間 | 9:00〜17:30 | プルダウン(15分刻み) |
| 3 | 休憩時間帯(昼休憩) | 12:00〜13:00 | プルダウン(15分刻み)。**必ず登録する**。開始を選ぶと終了は1時間後が入る |
| — | 1日の所定労働時間 | 7時間30分 | **自動計算(入力しない)**。勤務時間 − 休憩時間 |
| 4 | 所定労働日の曜日 | 月〜金 | 曜日ボタン(日曜始まり・複数選択) |
| 5 | 祝日を所定労働日から自動的に除外する | オン | チェック |
| 6 | 法定休日の曜日 | 日曜日 | プルダウン(日曜始まり) |
| 7 | 年間所定休日数 | 120日 | プルダウン(90〜145日) |
| 8 | 賃金締め日 | 末日 | プルダウン(末日 / 1〜31日) |
| 9 | 固定残業代(みなし残業) | なし(0円 / 0時間) | 金額入力 + プルダウン(0〜80時間・5時間刻み) |
| 10 | メイン画面に表示するもの(今日 / 今月) | 両方オン | チェック(片方だけなら横幅いっぱいに表示) |
| 11 | 自動モード | オフ | チェック |
| — | 標準勤務スケジュール | 出勤/退勤時間と共通 | 自動モード時に使用 |

出勤時間・退勤時間は自動モード専用ではなく、カレンダーから打刻を追記するときの初期値にも使う。
保存済みの設定値がプルダウンの選択肢に無い場合は、その値を選択肢に足してから選ぶため、設定が
勝手に変わることはない。

既定値の根拠: 厚生労働省「就労条件総合調査」(企業規模1,000人以上)で1日の所定労働時間は
おおむね7時間43分〜7時間47分。覚えやすい値として7時間30分を採用した。年間休日は同調査の
実態値(116.6日)と一般的な案内(120〜125日)の中間として120日とした。

## 4. 計算仕様

### 4.1 基礎時給単価

```
1日の所定労働時間 = (退勤 − 出勤) − 勤務時間と重なる休憩
                    ※ 休憩時間帯が未登録なら一律60分
年間所定労働日数   = 365 − 年間所定休日数           (うるう年も365固定)
月平均所定労働時間 = 年間所定労働日数 × 1日の所定労働時間 ÷ 12
基礎時給単価       = 基本給(+諸手当) ÷ 月平均所定労働時間
```

基礎時給単価の分子には、家族手当・通勤手当・住宅手当など個人の事情に応じて支給される手当を
**含めない**(労基則21条の除外規定に対応)。役職手当・資格手当などは含める前提で、設定画面では
「割増の基礎になる月額」として案内している。

既定値の場合: 年間245日 → 月平均153.125時間 → 基本給30万円なら **1,959円/時**。

端数処理は行わず、実数のまま積算する。

### 4.2 清算期間

賃金締め日を基準に、締め日の翌日から次の締め日までを1つの期間とする。

- 締め日が「末日」なら、その月の1日〜末日
- 締め日が20日なら、前月21日〜当月20日
- 31日締めで2月のように短い月は、その月の末日に丸める
- 期間ラベルは **期間末の年月**(8/21〜9/20 は「2026-09」)

### 4.3 所定労働日と2つの総枠

**所定労働日** = 会社休日に指定されておらず、国民の祝日でもなく(設定でオンの場合)、かつ
「所定労働日の曜日」に含まれる日。会社休日の明示指定は常に祝日判定より優先する。

```
所定労働時間の総枠 = 1日の所定労働時間 × 清算期間内の所定労働日数
法定労働時間の総枠 = 40時間 × 清算期間の暦日数 ÷ 7
```

フレックスタイム制(コアタイムなし)のため、**1日8時間超・週40時間超という日次/週次の
残業判定は行わない**。清算期間の累計実働時間を、期間の頭から順に次の順で消化していく。

```
① 所定内労働        … 所定労働時間の総枠に収まる分
② 法定内残業        … 所定の総枠は超えたが、法定の総枠には収まる分
③ 法定時間外労働    … 法定の総枠も超えた分(固定残業の有無・月60時間を境に扱いが変わる)
```

### 4.4 割増率

| 区分 | 倍率 | 深夜と重なる場合 |
|---|---|---|
| 所定内労働 | 1.00(基本給に含まれる分の取り崩し) | 1.25 |
| 法定内残業(所定超・法定内) | 1.00 | 1.25 |
| 固定残業でカバーされる分 | 固定残業代を時間で均した額(追加割増なし) | 同左 |
| 法定時間外労働(月60時間まで) | 1.25 | 1.50 |
| 法定時間外労働(月60時間超) | 1.50 | 1.75 |
| 法定休日労働 | 1.35 | 1.60 |

- 深夜(22:00〜翌5:00)は、他の割増に **+0.25** を加算する
- 所定内労働は法的には追加支払いのない区分だが、画面には基本給の日割り取り崩しとして
  1.00 で積み上げる。「基本給とは別の追加分」は内訳で別に示す
- **法定休日労働は、所定/法定の総枠にも月60時間ラインにも算入しない**(労基法上、休日労働は
  時間外労働に算入しないため)
- 所定休日(法定超・例: 土曜、または祝日除外がオフの場合の祝日)の出勤は35%増にはせず、
  通常の①②③の枠組みで計算する
- **国民の祝日は、実際に出勤すれば「所定休日(法定超)出勤」として通常どおり記録される**(所定/
  法定の総枠には算入されないため、その分早く割増区分に入りやすくなる)

倍率はすべて `src/constants.js` の `RATE` に集約してある。就業規則が法定を上回る場合は
そこだけを書き換えればよい。

### 4.5 固定残業代(みなし残業)

給与に固定残業代が含まれている場合の設定。法定時間外労働のうち、設定した時間までは追加の
割増を上乗せせず、固定残業代の月額を時間で均して積み上げる。超えた分から通常の割増
(1.25 / 1.50)が上乗せされる。

```
固定残業でカバーされる分の金額 = (固定残業代 ÷ 固定残業の時間) × その時点までの消化時間
```

- **固定残業代そのものは割増賃金なので、基礎時給単価の計算には含めない**
- **月60時間のラインは、固定残業でカバーされた分も含めた累計で判定する**(固定残業60時間の人が
  70時間働いたら、超過10時間は1.50倍)
- 固定残業代が、その時間ぶんの法定割増賃金額を下回っている場合は下回る定めが無効になるため、
  折りたたみの中で気づける程度に知らせる(警告表示ではない)

### 4.6 国民の祝日(`src/holidays.js`)

「国民の祝日に関する法律」に基づき、以下をすべて計算で求める。対象は2000〜2099年
(それ以外の年でも例外は投げないが精度は保証しない)。

- 固定日の祝日(元日・建国記念の日・天皇誕生日・憲法記念日・昭和の日・みどりの日・
  こどもの日・山の日・文化の日・勤労感謝の日)
- 何曜日の第何回で決まる祝日(成人の日・海の日・敬老の日・スポーツの日)
- 春分の日・秋分の日(1980〜2099年で有効とされる近似式による天文計算)
- 振替休日(祝日が日曜なら、祝日でない直近の平日まで飛ばして休日にする。2007年改正後のルール)
- 国民の休日(前後を祝日に挟まれた、それ自体は祝日でない平日)
- 2019年(改元)は天皇誕生日なし、2020・2021年(東京オリンピック特例)の海の日・山の日・
  スポーツの日の移動を反映

計算結果は実際の祝日カレンダーと突き合わせたテストで検証している(2024〜2026年の春分・秋分、
2026年のゴールデンウィークの振替休日連鎖など)。

### 4.7 休憩の自動控除

休憩は打刻せず、**登録した昼休憩の時間帯**(既定 12:00〜13:00、必須)と打刻区間が重なった分だけを
自動的に差し引く。加えて、その日だけ発生した休憩(打刻せず個別に時刻を記録)がカレンダーの
日編集から追加できる。

- 休憩時間帯に入っているあいだは **カウンターが止まる**(状態も「休憩中」になる)
- 重ならない日(午前半休で13:00から出勤など)は控除が発生しない。これは実態(その日は休憩を
  取らなかった)と一致しており、「休憩未取得の目安」がこのケースで意味を持つ
- リアルタイム表示の休憩控除は「休憩 0:06」のように符号なしの時間表記で示す

### 4.8 深夜労働

22:00〜翌5:00。打刻区間を深夜/非深夜に切り分け、深夜に重なる分だけ +0.25 を加算する。
日をまたぐ勤務にも対応する。**継続勤務が2暦日にわたる場合は、始業日の労働として通算する**
(行政解釈に基づく)。

### 4.9 有給休暇・会社休日・未入力日

| 種別 | 扱い |
|---|---|
| 有給休暇 | 打刻なしで1日の所定労働時間分を「所定内」として計上。時間外・深夜・休日の割増対象にはしない |
| 会社休日 | その日を所定労働日から除外する。未入力日にもしない。指定時に「法定休日」か「所定休日(法定超)」かを選ぶ(既定は法定休日の曜日から自動判定) |
| 会社休日への出勤 | 法定休日なら1.35倍。所定休日(法定超)なら通常の①②③ |
| 国民の祝日(未指定) | 会社休日を明示していなくても、設定がオンなら自動的に所定労働日から除外(4.6) |
| 未入力日 | すでに過ぎた所定労働日(祝日を除く)のうち、打刻も指定も無い日。**理由を問わず一律**「所定内・残業なし」として1日の所定労働時間分を自動加算する |

未入力日はいつでも後から実際の時刻を追記でき、追記すると通常の勤務日として再計算される。
追記は必須ではなく、アプリからの催促・通知は一切行わない(出張などで最初から打刻するつもりが
ない日を想定)。

## 5. 打刻の仕組み

### 5.1 手動モード(既定)

状態は `off` / `working` の2つだけ。**すべての打刻操作は確認ダイアログを挟む。**

- **出勤** — 押した時刻を記録し、その日が法定休日に当たるかを判定して保持する。すでに退勤済みの
  日にもう一度出勤を押した場合は、新しい記録を作らずに「退勤〜いままでを休憩」として同じ日の
  勤務を再開する(1日の記録は必ず出勤1回・退勤1回に揃える)
- **退勤** — 打刻区間をカレンダーに確定保存する。すでに確定済みの日にもう一度押した場合は、記録を
  増やさず退勤時刻をその時刻に更新する
- **休憩開始 / 休憩終了** — 何度でも記録できる。休憩中はカウンターが止まり、状態バッジも変わる。
  昼休憩の時間帯に入っているあいだは押せない(二重に休むことになるため)
- 日をまたいだ勤務は出勤日の記録として保存し、翌日には「継続日」の印を付ける(未入力日として
  二重に加算されないようにするため)
- 出勤したままブラウザを閉じても、次に開いたときに出勤時刻からの経過で再計算される(保存して
  いるのは時刻そのものであって、経過時間ではない)

### 5.2 自動モード

出勤/退勤ボタンを使わず、標準勤務スケジュールに沿って自動的に計測する。**手動の打刻は常に
自動モードより優先される**(押した時点でそちらが本物になる)。

| 状況 | 挙動 |
|---|---|
| 勤務予定時間内に開いた(手動の打刻なし) | 自動的にカウンターが動いている。ボタン操作は不要 |
| 昼休憩の時間帯 | カウンターが止まる |
| 退勤予定時刻を迎えた(残業開始を押していない) | そのまま自動的に確定する |
| 残業する日 | 勤務中に小さく出ている「残業開始」を **退勤予定時刻の前に** 押しておくと自動確定しない。実際に終えたら「残業終了」で確定 |
| **自動モード中に出勤ボタンを押す** | 押した時刻が出勤時刻になり、以後は手動の勤務として扱われる(状態は「勤務中」) |
| **自動確定のあとに退勤ボタンを押す** | 記録を増やさず、退勤時刻を押した時刻に更新する |
| 有給・会社休日・国民の祝日(除外設定オン) | カウンターは動かない |
| 所定労働日の曜日でない日 | カウンターは動かない |

内部的には「残業開始」= 退勤予定時刻での自動確定を無効化するフラグを立てるだけで、金額計算の
ロジックは手動モードとまったく同じものを使う。

## 6. 集計と表示

### 6.1 今日・今月の実働表示

「労働時間 / 所定労働時間」の形で、どこまで来ているかが分かるように表示する。今月は清算期間の
総枠、今日は1日の所定労働時間を分母にする(所定労働日でない日は分母を出さない)。

### 6.2 前月比較

月の途中で単純に合計を比べても先月が必ず多く見えるため、**同じ経過日数どうし** で比べる。

```
経過日数 N = 今日 − 清算期間の開始日 + 1
比較対象 = 先月の清算期間の開始日から N 日目までの実績
差 = 今月ここまで − 比較対象
```

今日カードの下に「先月比 ±◯◯円」を小さく添える。「先月との比較」の横棒グラフでは、今月・先月
(同じ経過日数点)を通常時間・残業時間の色分けで並べ、金額は出さず時間だけを見せる。先月の
データが無い場合(使い始めた最初の月)は「先月の記録がたまると比べられます」と表示する。

**この比較が変わるタイミング**: 今月側は他の数字と同じくリアルタイム(1秒ごと)。先月側は
基本的に日付が変わったとき(比較対象が1日ぶん伸びる)と、締め日を迎えたとき(比較の土台が
まるごと入れ替わる)にだけ動く。

### 6.3 残業時間の目安

金額計算には一切影響しない参考情報。

- 今月の法定時間外の実績。メイン画面には0〜60時間固定の横棒メーターで表示し、45時間・60時間・
  固定残業の位置に目印を置く。60時間を超えるとメーターが赤に変わり「(60時間超過)」と添える
- 折りたたみには、45時間・60時間・単月100時間(休日労働を含む)までの残り時間を数字で表示

45時間・360時間の判定は法定時間外労働で行い、単月100時間の判定には法定休日労働も加える。
**年間の累計や「月45時間超が年に何回か」といった複数月にまたがる管理は表示しない**(会社の
勤怠システムが行うべきものであり、個人の体感アプリで扱う情報ではないため)。ただし清算期間
ごとの残業時間サマリー(`wageOvertimeHistory`)自体は、締め日の処理で12ヶ月分の記録を今も
取り続けている(表示を復活させる場合に備えて)。

### 6.4 気づき表示

警告色・通知音・ポップアップは使わず、折りたたみの中に静かに置く。

- **休憩未取得の目安** — その日の実働が6時間(法定45分以上)・8時間(同60分以上)を超えているのに、
  昼休憩の自動控除が発生していない場合に表示する

## 7. データ保存(localStorage)

サーバーへは一切送信せず、その端末のブラウザ内(localStorage)にのみ保存する。家族それぞれが
自分の端末で開けば、それぞれ独立したデータになる(共有・同期はしない)。**保存されるのは
このアプリで打刻した記録と設定だけで、会社の勤怠システムとは連携しない。**

### 7.1 保存キー一覧

| キー | 内容 |
|---|---|
| `wageSettings` | 3章の設定一式(下記 7.2) |
| `wageState` | 出退勤の状態(下記 7.3) |
| `wageCalendar` | 日付ごとの記録。今月と先月ぶんのみ(下記 7.4) |
| `wageCurrentPeriodLog` | 進行中の清算期間の日別ログ(表示の再構築には使わず、バックアップ目的で1分おきに書き出す) |
| `wagePreviousPeriodLog` | 直前に確定した清算期間の日別ログ(前月比較・先月確定合計の表示に使用) |
| `wageOvertimeHistory` | 清算期間ごとの残業時間の合計だけを持つ軽量な配列(最大12ヶ月) |
| `wageTheme` | ライト / ダークの明示指定。`'light'` か `'dark'`。未保存なら常にライトで開く(2.1) |

上記とは別に、`localStorage` への書き込みが可能かを起動時に1回だけ `__wt_probe` というキーで
確認し、書き込み後すぐに削除する(プライベートブラウジングなどで保存できない環境の検出用)。

### 7.2 `wageSettings` の中身

```
{
  monthlyBaseSalary: number | null,   // 割増の基礎になる月額(円)
  dailyScheduledHours: number,        // 1日の所定労働時間(自動計算の結果を保存)
  annualHolidays: number,             // 年間所定休日数(日)
  closingDay: number | 'last',        // 賃金締め日(1〜31、または末日)
  legalHolidayWeekday: number,        // 法定休日の曜日(0=日〜6=土)
  workdays: number[],                 // 所定労働日の曜日の配列(例 [1,2,3,4,5]、日曜始まりで管理)
  observeNationalHolidays: boolean,   // 国民の祝日を所定労働日から自動除外するか
  breakWindow: { start: string, end: string } | null,  // 昼休憩の時間帯("HH:MM")
  fixedOvertimeAllowance: number,     // 固定残業代(円)。0なら無し
  fixedOvertimeHours: number,         // 固定残業の時間。0なら無し
  showToday: boolean,                 // メイン画面に「今日」を出すか
  showMonth: boolean,                 // メイン画面に「今月」を出すか
  autoMode: boolean,                  // 自動モード
  schedule: { start: string, end: string },  // 標準勤務スケジュール(自動モード用・打刻追記の初期値)
}
```

読み込み時、既定値(`WT.DEFAULT_SETTINGS`)とマージしてから使う。`workdays` が配列でない・
空の場合や `schedule` が壊れている場合は既定値に、`breakWindow` が無い・壊れている場合も
既定値(12:00〜13:00)に自動的に寄せる(過去バージョンの「休憩を登録しない」設定からの移行を
含む)。

### 7.3 `wageState` の中身

```
{
  status: 'off' | 'working',
  clockInAt: number | null,        // 出勤時刻(エポックミリ秒)。保存しているのは時刻そのもの
  isLegalHoliday: boolean,         // 出勤時点でその日が法定休日だったか
  lastClockOutAt: number | null,   // 前回の退勤時刻
  overtimeFlag: boolean,           // 自動モードの「残業開始」フラグ
  autoDayKey: string | null,       // 自動モードの残業フラグ・休憩をリセットする基準の日付("YYYY-MM-DD")
  periodStartKey: string | null,   // 現在の清算期間の開始日
  configured: boolean,             // 初期設定が完了しているか
  breaks: Array<{ start: number, end: number | null }>,  // その日の手動の休憩。終了前は end が null
}
```

`clockInAt` は「経過時間」ではなく「時刻」を保存しているため、ブラウザを閉じてから開き直しても、
開いた瞬間にその時刻からの経過で再計算される。

### 7.4 `wageCalendar` の中身

日付キー(`"YYYY-MM-DD"`)ごとに、次のいずれかの形のオブジェクトを持つマップ。

```
// 打刻あり(出勤した日。会社休日への出勤もここに入る)
{
  type: 'work' | 'company_holiday',
  holidayKind: 'legal' | 'scheduled' | undefined,  // company_holiday のときだけ意味を持つ
  clockIn: number,          // 出勤時刻(エポックミリ秒)
  clockOut: number,         // 退勤時刻
  isLegalHoliday: boolean,  // その日を法定休日として計算するか
  breaks: Array<{ start: number, end: number }>,  // 打刻せず記録した休憩
}

// 日をまたいだ勤務の、翌日以降の「継続日」の印
{ type: 'work', coveredBy: string }  // coveredBy は出勤日の日付キー

// 有給休暇
{ type: 'paid_leave' }

// 会社休日(打刻なし)
{ type: 'company_holiday', holidayKind: 'legal' | 'scheduled' }
```

指定の無い日付キーはマップに存在しない(未入力日か、国民の祝日として自動的に除外されている
かのどちらかを、`src/aggregate.js` が実行時に計算で判定する。保存はしない)。

### 7.5 締め日をまたいだときの処理(ロールオーバー)

日別の詳細ログ(`wageCalendar` / `wageCurrentPeriodLog` / `wagePreviousPeriodLog`)は今月と
先月の2期間ぶんだけを保持する。締め日を迎えたら次の順で処理する。**残業サマリーを履歴に
追記してから、詳細ログを破棄する** 順序を必ず守る。

1. 終わった清算期間を確定させる(未入力日の自動加算も含めて確定)
2. その期間の残業時間の合計を `wageOvertimeHistory` に追記(13ヶ月目の古い分は削除)
3. その期間の日別ログを `wagePreviousPeriodLog` に移す
4. `wageCalendar` から、先月の開始日より前の日付を削除する
5. 新しい清算期間をゼロから開始する(`wageCurrentPeriodLog` は空にする)

数ヶ月ぶりに開いた場合も、間の各期間がそれぞれ履歴に残る。削除は自動で行い、確認や警告は
出さない。

### 7.6 データが消える条件

以下のいずれかを行うと、保存されている設定・実績はすべて消える。復元手段はない。

- ブラウザの「閲覧履歴データを削除」「サイトデータを削除」等を行った
- シークレットモード / プライベートブラウジングで使っていた(タブを閉じた時点で消える)
- ブラウザアプリ自体をアンインストールした
- 端末を機種変更・初期化した(自動的な引き継ぎはない)
- 普段と違うブラウザや別の端末で開いた(ブラウザ+端末ごとに独立)
- ブラウザのストレージ容量が逼迫し、自動的にサイトデータが削除された
- ホーム画面に追加したアイコンを削除して入れ直した(再インストール扱いになることがある)

通常の再読み込み、ブラウザを閉じて開き直す操作、端末の再起動、オフラインでの使用では消えない。

## 8. 対象外・免責

- **非対象**: 社会保険料・所得税・住民税などの控除計算、年末調整、賞与計算。額面(グロス)の
  労働対価のみを可視化する
- **打刻は会社の勤怠システムとは別物**。表示される金額は体感用の目安であり、給与明細と一致しない
  ことは仕様として許容する
- コアタイムなしのフレックスタイム制(清算期間1ヶ月)を前提にしている。フレックスの労使協定が
  ない場合、清算期間が1ヶ月を超える場合、管理監督者・裁量労働制の場合は合わない
- 振替休日・代休、遅刻早退控除は扱っていない
- 本アプリは一般的に用いられる計算方法の実装であり、法律相談・労務相談・正式な給与計算の
  代替ではない。実際の運用では会社の就業規則・36協定の内容が優先される

## 9. 元の SPEC.md との違い

計算精度と使い勝手を優先して、次の点は元の仕様の字面から変えている。いずれも定数か関数
1つで元に戻せる。

| # | 内容 | 理由 |
|---|---|---|
| 1 | 休憩の自動控除は「実際に重なった分」だけ | 字面は「重なっていれば時間帯の長さ」だが、13:00出勤でわずかに掛かる日などが過剰控除になるため |
| 2 | 休憩時間帯が未登録のときの一律60分は、実働8時間かけて按分 | 出勤直後に60分まとめて引くと金額がマイナスから始まり、「開いた瞬間に増えている」体験が壊れるため |
| 3 | 法定休日労働を所定/法定の総枠・月60時間ラインに算入しない | 労基法上、休日労働は時間外労働に算入しないため |
| 4 | 設定に「所定労働日の曜日」を追加 | 総枠の計算に所定労働日数が必要で、毎月カレンダーで指定させるのは「操作は単純に」に反するため |
| 5 | 1日の所定労働時間は入力せず、勤務時間 − 休憩時間で自動算出 | 基本給・勤務時間・休憩時間を入れれば所定労働時間は決まるので、入力項目をひとつ減らせる |
| 6 | 覗き見防止のぼかしを廃止した | 増えていく数字が見えないとモチベーションにならない(SPEC 1.1 の目的)という判断による |
| 7 | 勤務間インターバルの目安を廃止した | 利用者の判断により、設定項目と表示の両方を削除 |
| 8 | 休憩は昼休憩(自動控除)とそれ以外(打刻せず個別記録)の二本立てにした | 「休憩は打刻しない」という原則は保ちつつ、実際には昼休憩以外にも休憩を取る実態に合わせた |
| 9 | 1日の記録を「出勤1回・退勤1回」に固定した | フレックスでは日中の出入り回数が賃金計算に影響しないため、途中の退出は自動的に休憩として扱う |
| 10 | 固定残業代(みなし残業)への対応を追加 | 実務でよくある給与形態のため |
| 11 | 国民の祝日の自動除外に対応した | 元の仕様は年間所定休日数(祝日込みの日数)だけを持ち、個別の祝日を所定労働日から外す仕組みが無かったため |
| 12 | 見た目をカード基調のダッシュボードにし、ライト/ダーク切替を追加 | 提示されたデザイン見本に合わせた |
| 13 | 36協定の年間集計(複数月にまたがる管理)の表示をやめた | 履歴が1年たまるまで意味を持たず、個人の体感アプリで扱う情報でもないため。今月ぶんの時間だけ残した |
| 14 | 曜日の並びを日曜始まりにした | 利用者の希望 |

そのほか、時間外労働の端数処理(1ヶ月合計の30分未満切り捨て等)は元の仕様どおり適用せず、
実数のまま表示・積算する。

## 10. 技術構成とテスト

フレームワーク・ビルド・依存パッケージなし。`index.html` を `file://` で直接開いても動くよう、
ES モジュールではなく素の `<script>` 分割 + `WT` 名前空間で構成している。

| ファイル | 役割 |
|---|---|
| `src/constants.js` | 割増率・深夜帯・36協定の目安・既定設定値 |
| `src/time.js` | 日付/時刻、深夜帯の分割、休憩帯の差し引き |
| `src/period.js` | 締め日から清算期間を算出 |
| `src/holidays.js` | 国民の祝日の計算(振替休日・国民の休日・特例年を含む) |
| `src/wage.js` | 基礎時給単価、休憩控除、区分計算(固定残業代を含む) |
| `src/aggregate.js` | 期間集計、有給・会社休日・未入力日・祝日、前月比較、残業メーターの見え方、気づき |
| `src/storage.js` | localStorage、締め日のロールオーバー、自動モードの状態解決 |
| `src/app.js` | DOM層(描画ループ・打刻・設定/カレンダー・テーマ)。ここだけが DOM に触れる |

`src/app.js` 以外は DOM に依存しない純粋関数の層。重い区分計算は1秒ごと、金額の描画は
`requestAnimationFrame` に分離しており、区分計算が重くなっても数字の動きは滑らかなまま保たれる。
